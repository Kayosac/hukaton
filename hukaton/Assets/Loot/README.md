# Лут

Всё о предмете хранится в одном ассете `LootItem`. Находки в мире, таблицы дропа врагов, учёт добычи за вылазку, лавка и витрина берут данные оттуда. Ассеты лежат в `Assets/Loot/`.

| Что | Где |
| --- | --- |
| Предметы | `Items/<id>.asset` |
| Каталог: все предметы, категории лавки, цвета редкости | `Loot catalog.asset` |
| Подбираемый предмет (база всех находок) | `Prefabs/Loot pickup.prefab` |
| Трофей, который выпадает из врага | `Prefabs/Loot drop.prefab` (назначен в `ExpeditionWorld → Loot drop`) |
| Предмет-рисунок | `Prefabs/Loot sprite.prefab` |
| Модели предметов (только меши) | `Prefabs/Models/` |
| Готовые находки для расстановки по уровню | `Prefabs/Finds/Find <id>.prefab` |
| Пулы находок (что окажется на месте находки) | `Pools/` |
| Диковины: FBX, текстуры, материалы | `Models/Curios/` (исходники и превью: `output/collectible-models/`) |
| Код | `Runtime/` (сборка `Hakaton.Loot`) |
| Проверки | `Tests/Editor/` (EditMode: `LootCatalogTests`, `LootTableTests`, `LootSpritePlacementTests`) |

## Новый предмет за 4 шага

1. **Создать ассет.** В `Assets/Loot/Items`: ПКМ → Create → Hakaton → Лут → Предмет. Имя файла совпадает с id.
2. **Заполнить поля.**
   - `id` — постоянный ключ: латиница в нижнем регистре, цифры и `_` (`bee_stinger`). По нему лавка и сохранения узнают предмет. Выпущенный id не менять.
   - `Display Name` — название в игре.
   - `Category` — одна из категорий каталога (`Находки`, `Трофеи`). Новая категория добавляется в список `Categories` каталога.
   - `Price` — рекомендованная цена в лавке. Её же показывает строка подбора.
   - `Rarity` — цвет блеска и строки подбора. На цену не влияет.
   - Вид, нужно хотя бы одно из трёх:
     - `Icon` — рисунок. Подходит для трофеев врагов. Настройки импорта PNG: Texture Type = Sprite (2D and UI), Mesh Type = Full Rect, Alpha Is Transparency. Pivot = Custom: X = 0.5, Y = нижняя граница видимого рисунка / высота PNG, считая снизу при alpha ≥ 128. Прозрачные поля сохраняются; пивот служит точкой опоры на полку. `Icon Height` задаёт высоту полного холста в метрах, включая прозрачные поля.
     - `Model` — 3D-модель для мира. Подходит для находок в лесу. Это префаб только с мешами: без скриптов, коллайдеров и Rigidbody, основание в нуле.
     - `Shelf Model` — отдельная модель для витрины, если нужна. Если поле пустое, на витрине показывается `Model`, а без модели рисунок.
   - `Notes` — пометки для разработки, в игре не видны.
3. **Добавить в каталог.** Открыть `Loot catalog.asset`, затем ⋮ → «Добавить все предметы проекта». Или перетащить предмет в список `Items`. Предмет, которого нет в каталоге, лавка не примет, и тогда отклоняется вся доставка вылазки.
4. **Сказать, откуда предмет берётся.**
   - **Из врага.** В префабе врага (`Assets/Game/Prefabs/<враг>.prefab`) у `WorldCreature → Drops` добавить строку: предмет, шанс от 0 до 1, количество от–до. Каждая строка бросается отдельно, так что может выпасть сразу несколько предметов. С галкой `At Least One` враг никогда не уходит пустым: если ни одна строка не сработала, выпадает одна из них, и строки с большим шансом выпадают чаще.
   - **Находка в мире.** Перетащить в уровень `Prefabs/Loot pickup.prefab` и указать `Item`. Если такой предмет будет встречаться часто, удобнее сделать префаб-вариант `Find <id>`. В редакторе модель предмета видна гизмо, а в игре строится внутри `Visual`. Если в `Visual` положить свою модель, используется она. Найденные предметы перечисляются в `ExpeditionWorld → Finds`. `Guaranteed` и `Spawn Chance` задают, появится ли находка на этой вылазке, а `Spawn Points` — где именно.

После правок запусти EditMode-тесты `LootCatalogTests` и `LootSpritePlacementTests` (Window → General → Test Runner). Каждая ошибка называет ассет и что в нём исправить.

## Как это работает

- **Подбор.** `WorldLoot` знает свой `LootItem`. При подборе `ExpeditionWorld.Collect(item)` записывает в учёт вылазки строку `LootSave {id, name, price, count}`. При возвращении `GameLoop` передаёт лавке пары id и количество. Лавка (`TradingPrototype`) при старте регистрирует все предметы каталога, так что любой предмет каталога можно доставить и продать.
- **Вид.** `LootCatalog.CreateVisual` создаёт вид предмета. В мире это `Model` или рисунок. На витрине и в руке продавца — `Shelf Model`, затем `Model`, затем рисунок. Предмет без коллайдера получает на витрине бокс по размерам, чтобы на него можно было навести прицел.
- **Редкость.** Цвета задаются в каталоге, в списке `Rarities`. `Tint Glint` выключен у обычных предметов: их блеск остаётся как в префабе.
- **Сохранения** хранят только id, поэтому переименовывать предмет и менять ему цену, вид или категорию можно свободно.

## Пулы находок и диковины

Находка с полем `Pool` (`WorldLoot.pool`) сама выбирает, каким предметом окажется, по весам пула (`LootPool`, Create → Hakaton → Лут → Пул находок). На готовой локации («Старая пасека») выбор делается заново каждую вылазку; в бесконечном мире — по зерну мира и месту, поэтому перезагруженный чанк показывает то же самое. Пустой пул — всегда предмет из поля `Item`.

| Место | Префаб | Пул | Что выпадает |
| --- | --- | --- | --- |
| Обычная находка (`find`, 9 точек пасеки) | `Find common_find` | `Pool find` | обычные ×1, необычные ×0,25 |
| Ценная находка (`find-hard`, 10 точек пасеки) | `Find special_find` | `Pool find-hard` | необычные ×1, редкие ×0,6 |
| Кристалл (`crystal`, дальнее кольцо) | `Find crystal` | `Pool crystal` | редкие ×1, легендарные ×0,8 |

В пулах сейчас 19 диковин (категория «Диковины»): 3D-модели из Blender, одна модель и для мира, и для витрины. Модели смотрят лицом в −X префаба (к камере витрины). «Лесная/Редкая находка» больше не выпадают, но остаются в каталоге ради сохранений.

Заменили FBX или текстуру в `Models/Curios/` — Tools → Hakaton → Лут → Подключить диковины (`CurioSetup`): импорт, материалы, префабы, предметы, каталог и пулы обновятся. Цены и редкость задаются там же, в таблице `Curios`; веса пулов — в `Pools`.
