# Единая игра Hakaton

Источник: Kayospace → Hakaton Concept Doc (`hakaton-f5xwo`), прочитана 08.11.2026 целиком. Последние фреймы «содержимое первой версии», «прогрессия и подготовка» и «стартовые параметры v0.1» уточняют ранние прототипы. Исходный снимок доски: `output/game-integration/concept-board.md`.

## Цель

Одна сохранённая редактируемая сцена: закрытая лавка → собранные колоды → физическая вылазка → возвращение с добычей → выкладка и торговля → покупки/улучшения → следующая вылазка. Суммарная выручка 1000 монет даёт поздравление; свободная игра продолжается. Начало: 0 монет, 0 товаров, готовые колоды. Все проверки только в Unity Editor, без сборки приложения.

## Аудит

Готовы отдельные авторские сцены лавки и мира, общий контроллер, торговля, NPC, кошелёк, мастерская, броски, существа и препятствия. Пробелы: дверь ведёт в тестовый двор; реальная добыча хранится отдельно от торгового запаса; встроенная мастерская не запускает вылазку; нет общего сохранения и цели. Карты/баланс пока соответствуют прежним демо, а не последнему пресету.

## Правила реализации

- Подсистемы остаются самостоятельными; интеграционный компонент связывает их через явные API и сериализованные ссылки.
- Сцена и префабы — источник структуры. Не создавать геометрию, UI, камеры и материалы в runtime.
- Для текущего прохода сохраняется существующий художественный материал; новые NPC не нужны. Арт старых карт не должен показывать неверные эффекты актуальных шести типов.
- Открытые параметры не выдаются за утверждённые: текущие потери при поражении 50% каждого типа с округлением вниз сохраняются как Inspector-настройка. Возврат блокирует повторные действия. Незавершённая вылазка не сохраняется посередине; восстановление — из последней безопасной лавки.
- Изменения пользователя в `AGENTS.md` и существующем `output/` не включать в наши коммиты автоматически.
